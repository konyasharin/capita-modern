# Архитектура

## Проекты

```
CapitaModern.csproj              Godot-проект (вид). Godot.NET.Sdk, net8.0
scenes/, scripts/                сцены и ноды, только отрисовка и ввод
src/CapitaModern.Core/           ядро симуляции, чистый C# без Godot
src/CapitaModern.Headless/       консольный прогон, dotnet run
```

Жёсткое правило: **в `Core` нет `using Godot`**. Ни `Vector2`, ни `GD.Print`, ни
`Node`. Взамен — `System.Numerics`. Это не эстетика: благодаря этому симуляция гоняется
тысячами тиков в консоли за секунды, без запуска редактора, и покрывается тестами.

Зависимости направлены в одну сторону: `Godot → Core`, `Headless → Core`.
`Core` не знает ни о ком.

## Где что лежит сейчас

`CapitaModern.Core` **пуст и пишется вручную владельцем проекта** — трогать его
не нужно. Пока ядра нет, вспомогательный код карты (`WorldMap`, `CountryTable`,
`ZoneGenerator`) временно лежит в `scripts/Map/` рядом с видом: это прототип, а не
окончательное место. Когда ядро появится, модель мира переедет в него, а в
`scripts/` останется только отрисовка.

## Тик

Симуляция идёт фиксированным шагом (1 тик = 1 игровой день). Скорость игры — это
сколько тиков в секунду выполняет вид, сама симуляция о времени не знает и `delta` не
принимает.

Порядок внутри тика:

```
1. экономика      производство, потребление, рынок, деньги
2. фронт          давление, изменение поля владения, размытие
3. связность      отрезанные территории теряют t
4. события        то, что произошло, складывается в очередь для вида
```

Между тиками вид интерполирует поле владения, иначе на скорости «1 тик/сек» граница
будет дёргаться (см. [`01-map.md`](./01-map.md)).

## Раскладка данных

Ядро оптимизируется под линейный проход, а не под красоту ООП:

- предприятия, ячейки поля, рынки — **плоские массивы по полям** (SoA);
- id — целочисленные индексы в массивы, не ссылки на объекты;
- ничего не аллоцируется в тике; буферы переиспользуются;
- «активные» подмножества (фронтовые ячейки, грязные чанки) держатся отдельными
  списками, чтобы не обходить всю карту каждый тик.

Это единственное место, где стоит заранее думать о производительности. Всё остальное
можно писать как угодно.

## Данные игры

Товары, рецепты, типы предприятий, страны, стартовый сценарий — в JSON в `data/`, не в
коде. Ядро грузит их через простые DTO. Правка баланса не должна требовать пересборки.

Файлы читает вид (`Godot.FileAccess`, работает и из `res://`, и из `.pck`) и передаёт
в ядро уже байтами или строкой; `Headless` читает те же файлы обычным `File`. Ядро
само ничего не открывает — иначе оно узнало бы про пути Godot.

**Не забыть при первом экспорте:** `.bin` и `.json` не являются ресурсами Godot, и в
`.pck` они не попадут без явного `include_filter` вида `data/*` в настройках экспорта.

## Сейв

Сейв — полный дамп состояния ядра (поле владения, предприятия, рынки, казна, дата).
Поле владения сжимается тривиально (RLE по `owner`). Никакой инкрементальности.

Из этого следует требование детерминизма: одинаковый seed + одинаковая
последовательность команд игрока = одинаковый мир. Поэтому все случайности берутся из
явного генератора, хранящегося в состоянии, а не из `Random.Shared` и не из времени.

## Граница вид/ядро

Вид умеет ровно три вещи:

1. читать состояние ядра для отрисовки;
2. отправлять в ядро команды игрока (построить, распределить усилие, объявить войну);
3. дренить очередь событий для эффектов.

Никакой игровой логики в `scripts/`. Если в ноде появляется расчёт — он написан не там.
