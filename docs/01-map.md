# Карта, владение, границы

Самый важный документ проекта. Всё остальное строится поверх этой модели.

## Модель владения

Мир — прямоугольная сетка ячеек. В каждой ячейке:

```
owner : byte   — id страны-владельца (0 = ничьё/вода)
t     : float  — «прочность» владения, 0..1
```

Значение `t` трактуется как **высота над уровнем моря владения**: `t = 0.5` — ровно
линия границы, `t > 0.5` — уверенно внутри страны, `t < 0.5` — уже фактически потеряно.

Граница страны `C` — это **изолиния уровня 0.5** функции

```
f_C(cell) = owner == C ?  t  :  1 - t
```

### Почему именно так

Это единственное решение всех требований разом:

- **Плавность.** Изолиния берётся с субклеточной точностью (интерполяция внутри
  ячейки). Меняем `t` на 0.01 — граница сдвигается на сотую долю ячейки. Дискретность
  сетки в кадре не видна.
- **Дешевизна.** Сетка 1024×512 = 524 288 ячеек, это 0.5 МБ на `owner` + 2 МБ на `t`.
  За тик пересчитываются только ячейки у фронта (сотни-тысячи), а не вся карта.
- **Топология бесплатно.** Анклавы, окружения, прорывы, слияния территорий возникают
  сами собой. Не нужен ни граф регионов, ни ручная обработка случаев.
- **Красота бесплатно.** Лёгкое размытие поля после каждого тика убирает иглы и
  зазубрины, фронт сам собой остаётся гладким.

## Рендер границ

CPU не строит геометрию границ. Поле заливается в текстуру, всё рисует шейдер.

```
CPU:  поле владения ──(только изменённые чанки)──> текстура R8 (owner) + R16F (t)
GPU:  фрагментный шейдер:
        1. sample поля в окрестности 3×3
        2. + fbm-шум небольшой амплитуды     ← органичная изрезанность
        3. изолиния 0.5 → маска страны
        4. заливка цветом + контур через smoothstep(fwidth(...))  ← антиалиасинг
```

Три следствия:

- **Шум вместо детализации.** Хранить детальные изгибы границы не нужно: сетка задаёт
  крупную форму, а `fbm`-шум добавляет мелкие изгибы. Шум привязан к мировым
  координатам, поэтому он неподвижен, а граница по нему «ползёт» — выглядит так,
  будто у границы есть настоящая мелкая география.
- **Бесконечный зум.** Граница остаётся гладкой на любом приближении, потому что
  считается в экранном пространстве, а не хранится точками.
- **Ноль CPU на отрисовку.** Обновление текстуры — только для «грязных» чанков 64×64.

### Многострановость в шейдере

`owner` нельзя интерполировать (среднее между id 3 и 7 — не id 5). Поэтому шейдер
берёт 3×3 nearest-выборку, набирает веса по каждому встреченному id и берёт максимум.
Плавность даёт не фильтрация текстуры, а веса. Практический предел — 2-3 страны на
одну точку экрана, чего достаточно всегда, кроме стыков трёх границ.

### Вода и побережье

Береговая линия должна совпадать с границей точно, иначе «поплывёт» и станет уродливо.
Поэтому суша тоже хранится как поле (SDF расстояния до берега), и маска страны
пересекается с маской суши **до** взятия контура. Береговая часть границы рисуется
другим стилем (без жирной линии, только тень).

## Связность

Изолинейный подход честно рисует любые кляксы, в том числе отрезанные при прорыве
куски территории. Чтобы карта не превращалась в леопардовую шкуру:

- территория без связи со столицей теряет `t` со временем и схлопывается;
- очаги меньше порогового размера гасятся тем же размытием;
- размытие поля после тика — главный инструмент опрятности карты.

## Параметры (стартовые, подлежат подбору)

| Параметр | Значение | Комментарий |
|---|---|---|
| Сетка | 1024×512 | 0.5 М ячеек, ячейка ≈ 25-40 км |
| Чанк обновления | 64×64 | единица заливки в текстуру |
| Стран | ≤ 64 | влезает в `byte` с запасом на спецзначения |
| Тик симуляции | 1 день | скорость игры = тиков в секунду |
| Амплитуда шума границы | 0.3-0.6 ячейки | подбирается на глаз |

## Интерполяция между тиками

Тиков в секунду мало (1-10), поэтому вид хранит `t` предыдущего и текущего тика и
интерполирует их при отрисовке. Иначе на медленной скорости граница будет дёргаться
раз в секунду вместо непрерывного движения.

## Риск

Это самая сложная часть проекта. Делается первой, отдельным прототипом, до всякой
экономики: поле + шейдер + ползущий фронт по нажатию клавиши. Если гладкость и
скорость устраивают — дальше всё просто.
