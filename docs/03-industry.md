# Промзоны и предприятия

## Роль промзоны

Промзона — **группировка для игрока, а не игровая механика**. Она даёт:

- место, где кучкуются предприятия (карта читается: видно, где промышленность);
- окно со списком и статистикой по содержимому;
- статистику по части промзоны, если её разрезала граница.

Промзона не даёт бонусов, не ограничивает застройку и не является единицей владения.
Владение определяется исключительно полем под координатой конкретного предприятия.

## Координаты внутри промзоны

Промзона — прямоугольник в мировых координатах, условно 100×100 внутренних единиц.

**Важно:** это не 10 000 слотов-объектов. Это диапазон координат. Предприятие хранит
`x, y` как два `ushort` — 4 байта. Никакого массива на 10 000 ячеек не существует и не
нужно: пустая позиция не занимает ничего, потому что её нет.

При постройке позиция выбирается случайно из свободных (детерминированно от seed мира,
чтобы сейв/загрузка давали ту же картинку) с проверкой на пересечение с уже
занятыми — это перебор по списку предприятий промзоны, десятки элементов.

Стоимость: **ноль**. Разрешение 100×100 можно поднять до 1000×1000 без каких-либо
последствий для производительности, потому что хранятся только занятые точки.

## Реальное узкое место

Оно не в координатах, а в **количестве живых предприятий**, каждое из которых каждый
тик что-то производит, потребляет и торгует.

| Масштаб | Предприятий всего | Оценка |
|---|---|---|
| Комфортно | 5 000 - 20 000 | тик экономики единицы мс |
| Терпимо | до 50 000 | нужен аккуратный код, SoA-раскладка |
| Плохо | 100 000+ | глубину экономики придётся резать |

Ориентир: ~200-500 промзон по 20-60 предприятий. Если хочется «тысячи заводов в одной
промзоне» — это упрётся не в отрисовку, а в экономический тик.

Отсюда требование к `CapitaModern.Core`: данные предприятий лежат **плоскими массивами
по полям** (структура из массивов, не массив объектов). Тик — линейный проход по
массивам, без аллокаций и без виртуальных вызовов. Это разница между 2 мс и 200 мс.

## Отрисовка

Ни в коем случае не нода Godot на предприятие. 20 000 нод — это заведомо мёртвый кадр.

- один `MultiMeshInstance2D` на всю страну/весь мир, инстанс = квад предприятия;
- позиция и тип пишутся в per-instance данные, обновляются только при изменениях;
- отсечение по видимой области;
- LOD: на дальнем зуме промзона — один закрашенный прямоугольник с числом, отдельные
  предприятия не рисуются вовсе.

При таком подходе 20 000 предприятий — это несколько draw call'ов и никакой нагрузки.

## Разрез границей

Промзона не знает, кому она принадлежит. При открытии окна:

1. берём список предприятий промзоны;
2. для каждого смотрим `owner` поля в его координате;
3. группируем по владельцу.

Игрок видит статистику своей части. Пересчёт нужен только для промзон, которых
касается фронт — их единицы.

Визуально разрез показывается тем же контуром границы, который просто проходит поверх
промзоны. Специальной обработки не требуется.

## Открытые вопросы

- Промзоны появляются сами (по ресурсам/населению) или их основывает игрок?
- Можно ли строить вне промзон? Если нет — промзона всё-таки становится механикой.
- Что происходит с предприятием, оказавшимся ровно на линии фронта: работает,
  простаивает, разрушается?
